# Adaptive Split Inference of Transformer-Based NLP Models in MEC Using Reinforcement Learning

Исследовательский программный комплекс и симулятор **адаптивного разделённого инференса (Adaptive Split Inference)** моделей класса Transformer в средах мобильных граничных вычислений (**MEC — Mobile Edge Computing**) с использованием обучения с подкреплением (**RL**) и дискретно-событийного моделирования (**SimPy DES**).

## О чём проект простыми словами

Запуск тяжёлых NLP-трансформеров (например, для классификации текста / фильтрации спама) на мобильном устройстве упирается в два ограничения:
- **Полный локальный расчёт на смартфоне (`Local Inference`)** предсказуем, но сильно нагружает CPU и быстро разряжает батарею.
- **Полная отправка запроса на сервер (`Full Offloading`)** экономит заряд телефона, но при перегруженной сети или очереди на сервере резко растёт задержка и срывается дедлайн (SLA).

**Идея Adaptive Split Inference:** не привязываться жёстко к одному варианту, а на каждом входящем сообщении динамически выбирать три параметра:
1. **Точку разрезания нейросети `k` (`0 .. L`)**: первые `k` слоёв Трансформера выполняются на смартфоне, промежуточный тензор отправляется по сети, а оставшиеся `L - k` слоёв дочитываются на MEC-сервере (`k = 0` — полная выгрузка, `k = L` — полностью локально).
2. **Битность квантования активаций `b` (`32`, `16`, `8` или `4` бита)**: сжимает промежуточный тензор перед отправкой по радиоканалу (до ~8× при `INT4`).
3. **Частоту процессора смартфона `f` (DVFS)**: снижает или повышает тактовую частоту CPU, балансируя между скоростью и энергопотреблением батареи.

Агент учитывает сразу три критерия: **итоговую задержку (Latency)**, **энергопотребление смартфона (Energy)** и **сохранение точности модели (Quality / Accuracy)** при штрафах за нарушение SLA.

## Как устроена система (архитектура решения)

```text
[ Текст / SMS ]
       │
       ▼
[ Токенизация ] ──► [ Состояние MEC: канал, загрузка сервера, длина текста, CPU ]
                                         │
                                         ▼
                        [ Политика / RL-агент: выбор (k, b, f) ]
                                         │
         ┌───────────────────────────────┴───────────────────────────────┐
         ▼ (слои 0 .. k-1)                                               ▼ (слои k .. L-1)
[ Смартфон (PyTorch + DVFS) ] ──► [ Квантование FP32/INT16/INT8/INT4 ] ──► [ Радиоканал + Очередь SimPy DES ] ──► [ MEC-сервер ]
                                                                                                                          │
                                                                                                                          ▼
                                                                                                              [ Ответ (SPAM/HAM) + Метрики ]
```

Ключевые технические особенности:
- **Gymnasium + SimPy Discrete-Event Simulation (`simulation/`)**: среда `MECSimulationEnv` использует `SimPyDESEngine` (`simpy.Environment` и `simpy.Resource`) для моделирования разделяемого беспроводного канала, очереди на MEC-сервере и фонового пуассоновского трафика.
- **Реальный PyTorch Split Inference (`models/`)**: граф `ModularTransformer` физически разрезается на слое `k`. В модуле `ActivationQuantizer` реализовано квантование `FP32`, `INT16`, `INT8` и `INT4` (с физической упаковкой двух 4-битных значений в один байт `uint8`), а также контроль качества (`Cosine Similarity`, `SNR`, совпадение предсказания с эталонным `FP32`).
- **Реальная NLP-задача «Спам / Не спам» (`models/spam_classifier.py`)**:
  - встроенный сбалансированный набор EN + RU сообщений (160 текстов);
  - загрузка академического датасета **UCI SMS Spam Collection** (5 574 реальных SMS);
  - поддержка собственных CSV/TSV-файлов (колонки `label, text` или `v1, v2`);
  - обучаемый офлайн-классификатор `ModularSpamClassifier` и опциональная поддержка предобученного HuggingFace `DistilBERT` (при наличии пакета `transformers`).

## Реализованные алгоритмы принятия решений

В системе сравниваются **8 политик** (5 базовых/эвристических и 3 RL-агента):

| № | Алгоритм | Тип | Как работает |
|---:|---|---|---|
| 1 | `Local Inference` | Базовый | Все слои считаются на смартфоне (`k = L`). Нет сетевой передачи, высокий расход батареи. |
| 2 | `Full Offloading` | Базовый | Сырые токены сразу отправляются на сервер (`k = 0`). Минимум энергии на устройстве, но сильная зависимость от сети. |
| 3 | `Fixed Split` | Базовый | Всегда режет модель на фиксированном слое (например `k = 3`, `b = 8` бит) без подстройки под сеть. |
| 4 | `Greedy Adaptive` | Эвристика | На каждом шаге аналитически оценивает допустимые `(k, b, f)` и выбирает минимум мгновенной функции стоимости. |
| 5 | `Random Policy` | Базовый | Случайный выбор действий — нижняя контрольная планка. |
| 6 | `DQN` | RL | Deep Q-Network с Replay Buffer и Target-сетью по дискретной сетке действий. |
| 7 | `PPO` | RL | Proximal Policy Optimization с тремя независимыми категориальными головами `(k, b, f)`, GAE и clipped objective. |
| 8 | `SAC` | RL | Дискретный Soft Actor-Critic с двумя Q-критиками и энтропийной регуляризацией. |

## Сетевые сценарии симулятора

Среда поддерживает **5 воспроизводимых сценариев** (задаются через `seed` и параметр сценария):

- **`stable`** — стабильный 5G/Wi-Fi канал (~65 Мбит/с, задержка распространения ~8 мс).
- **`fluctuating`** — переменная пропускная способность (15–75 Мбит/с) и колебания задержки (10–35 мс).
- **`congested`** — перегруженная базовая станция и очередь на сервере (5–18 Мбит/с, RTT 40–95 мс).
- **`poor`** — плохое покрытие сотовой сети (низкая скорость, высокая задержка).
- **`random`** — случайное стохастическое изменение параметров канала на каждом шаге.

## Установка и запуск

### Требования
- **Python 3.10+** (проверено на 3.10 / 3.11)

### 1. Создание окружения и установка библиотек

```bash
python3 -m venv venv

# Linux / macOS:
source venv/bin/activate
# Windows (PowerShell):
# .\venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

### 2. Запуск веб-дашборда (Streamlit)

```bash
streamlit run app.py
```

После запуска интерфейс откроется в браузере по адресу `http://localhost:8501`.

### 3. Запуск CLI-эксперимента по классификации спама (NLP + MEC)

```bash
# Базовый прогон на встроенном EN+RU датасете (сценарий congested)
python run_spam_experiment.py

# Скачать и прогнать на реальном UCI SMS Spam Collection (5574 SMS) + дообучить PPO
python run_spam_experiment.py --dataset uci --epochs 10 --scenario congested --max-test 200 --train-ppo

# Запустить на своём CSV-файле (колонки label, text)
python run_spam_experiment.py --dataset csv --csv-path path/to/messages.csv --scenario poor
```

Итоговая таблица с `Accuracy`, `F1`, `FP32_Match%`, средней/P95 задержкой, энергией и SLA автоматически сохраняется в `results/`.

### 4. Консольные демо-сценарии симулятора

```bash
# Сравнение стратегий при резком ухудшении качества канала
python demo_scenario.py

# Консольный бенчмарк политик
python run_demo.py
```

## Интерфейс Streamlit (7 вкладок)

1. **`1. Overview & Architecture`** — схема разделения вычислений и текущие параметры сети/устройства/сервера.
2. **`2. Simulation Configuration`** — настройка параметров модели (`L`, `d`, длина текста), энергопрофиля смартфона (DVFS) и весов целевой функции.
3. **`3. Live Simulation & Partitioning`** — ручной выбор `(k, b, f)` с визуализацией слоёв (смартфон / квантованная передача / сервер) и мгновенным расчётом задержки и энергии.
4. **`4. RL Agent Training`** — обучение `PPO`, `DQN` и `SAC` прямо в интерфейсе, графики наград/лосса и сохранение чекпоинтов.
5. **`5. Algorithm Comparison`** — честный бенчмарк выбранных алгоритмов на одном seed, графики Latency / Energy / Payload / Reward и экспорт в CSV.
6. **`6. Results & Scientific Analysis`** — анализ сохранённых экспериментов, построение компромисса «Задержка vs Энергия» и относительного выигрыша.
7. **`7. Real Spam Detection (NLP + MEC)`** — сквозная проверка на реальных текстах:
   - выбор датасета (встроенный EN+RU, скачивание UCI SMS Spam Collection, загрузка своего CSV/TSV);
   - обучение/загрузка `ModularSpamClassifier` (или предобученного HuggingFace `DistilBERT`);
   - интерактивная проверка любого сообщения с выводом вердикта `SPAM` / `HAM`, выбранного `(k, b, f)`, объёма переданных байт и задержки SimPy;
   - пакетный тест по всем политикам и битностям с матрицей ошибок (Confusion Matrix), `Accuracy`, `Precision`, `Recall`, `F1` и выгрузкой CSV.
